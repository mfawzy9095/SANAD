# 9.2.8: cash debit and observation regressions

This release is a QA candidate, not a financial-completeness claim. Private financial data is excluded from this repository.

## Root causes and checks

- Egyptian debit-card ATM terminal identifiers such as `ATM987` did not match the word-boundary regex, causing a cash debit to be classified as consumption. Test failed with purchase versus withdrawal before changing the pattern. Ordinary merchant purchases remain eligible.
- Withdrawal routing discarded the uniquely matched payment instrument's linked account. Use that account as the source, reject conflicting card/account identities, and retain cash-destination review when no unique destination exists. The regression checks both asset legs, net conservation and repeat import.
- Observation-only plans updated the account observation but skipped the reconciliation snapshot because the UI method required a transaction. The real inbox/mutation harness reproduced the stale snapshot across persistence. Observation plans now update the snapshot too.
- Available balance must not be compared with calculated ledger balance. The real inbox test reproduced a false difference on a known opening balance. Only explicit ledger-balance evidence is comparable.
- Source-specific Egyptian full day/month/year dates were not extracted, resulting in an invalid-date review for valid dates. Extract the explicit bank date, keep calendar validation, and leave ambiguous generic dates under review.

## Data correction

`tools/quarantine-atm-purchases.js` validates source fingerprint and references, then proposes copy-only quarantine of explicit NBE debit-card messages at identified NBE/HDB ATM terminals. It does not invent cash destinations. Every removed confirmed posting remains in the private rollback journal and review queue with a durable hold and its original transaction identity. User financial overrides are preserved. The original diagnostic snapshot is retained and marked as such; it is not regenerated device telemetry.

Usage: `node tools/quarantine-atm-purchases.js ORIGINAL.json NEW_DIRECTORY apply-copy`.
Restore original bytes with the exported `rollback(repairedBytes,journal)` function. This verifies both hashes.

## Remaining boundaries

No bank-statement oracle, physical Samsung test or universal SMS grammar is claimed. Source/account ownership ambiguities, cancelled history scans, unidentified merchants/wallet funding and partial opening balances prevent financial certification. Valid generic incoming transfers and card-payment acknowledgements still need origin/route evidence. Existing records are not silently reclassified by this app update.
