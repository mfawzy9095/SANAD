# 9.2.14: composite settlement evidence and notification controls

Phase remains open. No private message/backup data is part of this change.

## Reproduced financial defect

A completed settlement containing two original references or dates could select the first matching field and automatically update a pending purchase. The new regression fails on 9.2.13 (`auto-save` instead of `review`). A message with conflicting card identities has the same risk. A single strong-looking fragment is not sufficient proof when the rest of the message contradicts it.

The settlement adapter now requires a single occurrence of each labelled amount, fee, original reference, original date and card identity. Repeated labels, including mixed Arabic/English labels, receive a distinct ambiguous-evidence review reason. Settlement references cannot be truncated at forty characters and treated as a match. Card identity requires an explicit ending/last-four assertion; cardholder IDs, issue years and longer numbers cannot be treated as a card suffix. A second red/green regression demonstrates the generic nearby-number fallback incorrectly matching these contexts before this guard. A complete unambiguous proof still settles the same purchase with separate fees; this does not block all settlements or silently rewrite historical decisions.

The actual browser import test retains a composite proof in durable review, reloads, verifies the original purchase remains pending and its balance unknown, then imports an independent unambiguous proof and verifies the existing purchase is settled once. Synthetic core tests cover conflicting references/dates/cards in both languages and retain the previous success, backup, fee and storage-failure checks.

## Android notification controls

The foreground service requests immediate notification visibility so that a user-started import exposes its pause/cancel controls promptly. [Android Notification.Builder.setForegroundServiceBehavior](https://developer.android.com/reference/android/app/Notification.Builder#setForegroundServiceBehavior(int)) documents that default foreground notifications may be deferred, while FOREGROUND_SERVICE_IMMEDIATE prevents that deferral. This changes visibility, not posting or durability.

Native CI now opens the actual Android notification drawer and taps the real pause/cancel PendingIntents during unfinished provider scanning. It verifies durable paused/cancelled status, unchanged ledger, resume-to-end after pause, and refusal to resume an explicitly cancelled checkpoint. Existing Home/background and force-stop/cold-resume tests remain. Results must be taken from the final commit's CI artifact; no claim of Samsung-specific behavior is made.

## Remaining gates

Stable QA signing key, Samsung S25 FE/hardware biometric/storage-pressure checks, wider bank-specific message coverage, and official logo redistribution rights remain separate unresolved gates. This batch does not claim universal bank parsing or a compatible signed update.

The first native action test failed because it inspected only the visible notification shade without scrolling. The retained UI hierarchy shows the SANAD notification in the shelf below expanded Messages notifications. The driver now scrolls the actual shade and expands the matching notification; it retains the financial/status assertions and does not replace the tap with a JavaScript or service call. The final CI must prove the corrected interaction.
