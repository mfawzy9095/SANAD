# 9.2.11 SMS template variants — phase remains open

A debit-card charge notification with the currency present only beside the charge was rejected because its trailing balance was required to repeat a currency. The Egyptian bank adapter now accepts that documented template variant while keeping its issuer and card-type scope. Arabic ATM withdrawal wording and explicit English purchase wording without a card suffix are understood. Missing card identity remains review; the parser does not invent a suffix or route to the only account.

Generic account debits now carry `debit_notice` / `debit-purpose-required`, with an Arabic explanation. A debit alone does not establish expense, transfer, repayment, or fee. Both ingestion and transaction construction retain the review gate.

Synthetic regression `sms-template-variants.test.js` failed before the fix and passes after it. It verifies five positive interpretation cases and two negative controls. A separate six-case acceptance slice has one expected auto-save, five review outcomes (including two non-completed controls), four recognized events, and zero incorrect auto-posts. These denominators apply only to that declared slice; they are not a production error-rate estimate. All 46 JavaScript test files pass locally.

Private source messages and identifiers are excluded from the repository. Local replay counts measure recognition, not financial correctness. Existing historical transactions were not modified. Broad multilingual interpretation, revocable learning, complete pending FX settlement reporting, late settlement reconciliation, native background execution, physical-device storage/process-death validation and official bundled logos remain open as described in prior reports. No universal-bank support claim is made.

An additional negative regression preserves an explicitly different observed-balance currency; accepting an omitted unit must never relabel an explicit unit. The regression failed before that guard and passes after it.

Android run 37571264897 failed at DevTools `Runtime.enable` before any financial assertion. Its old discovery selected the first WebView socket from any process and the first page, without proving that either belonged to SANAD or had reached its asset URL. The harness now waits for the package PID's socket and the exact asset page, recording target discovery and failure logcat. Deterministic tests cover an unrelated socket, an initially blank page, an unrelated first page, and bounded failure. Financial assertions and command timeouts are unchanged. The original run lacked target diagnostics, so its precise underlying timeout cause is not claimed as proven. A fresh full CI run is required.
